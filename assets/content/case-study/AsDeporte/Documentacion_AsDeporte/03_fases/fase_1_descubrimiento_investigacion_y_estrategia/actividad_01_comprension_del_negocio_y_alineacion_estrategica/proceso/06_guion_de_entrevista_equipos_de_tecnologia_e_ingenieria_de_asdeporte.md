(5-20 min) Arquitectura y Base Tecnológica

●  Actualmente, ¿cómo describirían la arquitectura de las plataformas digitales de
AsDeporte (web, APIs, bases de datos, aplicaciones móviles)? ¿Son sistemas
separados, o hay una base de código/arquitectura compartida? [Source 47]

●  El brief menciona "desarrollo de una nueva plataforma" y el análisis "plataforma
tecnológica robusta". ¿Esto significa una reconstrucción completa de la
arquitectura central, o una evolución y rediseño importante sobre la base
existente? ¿Cuáles son los principales impulsores de este enfoque elegido? [Source
47]

●  ¿Cuáles son las principales tecnologías (stack tecnológico) que se utilizan
actualmente o se planean utilizar para el desarrollo de esta nueva plataforma
(lenguajes de programación, frameworks, bases de datos, infraestructura cloud)?
[Source 47]

(20-35 min) Restricciones Técnicas y Desafíos Conocidos

●  Desde una perspectiva técnica, ¿cuáles son las limitaciones más significativas o
los puntos débiles que han identificado en la plataforma actual que necesitamos
superar o tener muy presentes al diseñar? (Ej. bases de datos legadas que imponen
restricciones, deuda técnica acumulada, limitaciones de rendimiento, dificultades de
escalabilidad, APIs internas con baja documentación o fiabilidad). [Source 2384,
Source 18]

●  ¿Hay restricciones técnicas específicas relacionadas con el rendimiento, la

seguridad o la escalabilidad que debamos considerar desde el diseño para asegurar
que la plataforma pueda manejar un alto volumen de usuarios y picos de tráfico (ej.
durante inscripciones masivas)? [Source 46, Source 50]

●  La plataforma manejará datos sensibles (financieros, de salud, localización).
¿Existen requisitos técnicos específicos de seguridad o cumplimiento
normativo (aparte de las mejores prácticas generales) que deban guiar el diseño de
flujos o la gestión de datos? [Source 50, Source 2312]

●  ¿Tenemos APIs internas o externas existentes (para pagos, mapas, comunicación,
wearables) con las que la nueva plataforma debe integrarse? ¿Hay alguna limitación
conocida con estas APIs? [Source 49, Source 2383]

●  ¿Cómo visualizan la gestión de datos a gran escala para funcionalidades como
"Race Insights" y potencial personalización? ¿Esto requiere una infraestructura
técnica específica que deba considerarse en el diseño? [Source 15, Source 51,
Source 235]

(35-45 min) Factibilidad del Alcance MVP y Colaboración Diseño-Desarrollo

●  Revisando la lista de funcionalidades clave planeadas para el MVP

(Exploración/Búsqueda Eventos, Registro/Pago, Perfil, Tribu, B2B básico, etc.), ¿ven
alguna funcionalidad que represente un riesgo técnico significativo o que estimen
que requerirá un esfuerzo de desarrollo considerable?

●  Para el módulo básico de organizadores B2B (web) en el MVP, desde una

perspectiva técnica, ¿cuáles son las funcionalidades mínimas esenciales que
consideran factibles y realistas para un primer lanzamiento, dadas las posibles
restricciones de tiempo y recursos?

●  ¿Cuál es el tamaño y la experiencia del equipo de desarrollo que se asignará a
este proyecto? ¿Cómo impacta esto en la complejidad de las soluciones que
podemos diseñar para el MVP?

●  ¿Cómo sería la colaboración ideal entre el equipo de Diseño (nosotros) y el equipo

de Desarrollo (ustedes) a lo largo del proyecto? ¿Con qué frecuencia y en qué
momentos deberíamos sincronizarnos? [Source 2870, Source 104, Source 49]
●  ¿Cómo prefieren recibir las especificaciones de diseño y los assets (ej. Zeplin,

Figma Dev Mode, Storybook)? ¿Hay un formato de handoff que funcione mejor para
su equipo? [Source 2875, Source 2160, Source 189]

●  ¿Hay una metodología de desarrollo (ej. Scrum, Kanban) que se utilizará y con la

que el proceso de diseño deba alinearse? [Source 65]

(45-55 min) Perspectiva Técnica General y Cierre

●  Desde una perspectiva técnica, ¿cuál es el mayor desafío que ven en la

construcción exitosa de esta nueva plataforma integral?

●  ¿Y cuál es la mayor oportunidad técnica que este proyecto les permite abordar?
●  ¿Hay algo más fundamental sobre la infraestructura, la tecnología o el proceso de

desarrollo que debamos comprender como diseñadores para asegurar que nuestro
trabajo sea técnicamente factible y optimizado?

●  ¿Hay alguna persona clave adicional en el área de Tecnología/Ingeniería (ej.

especialistas en bases de datos, seguridad, QA, arquitectos) con la que sería valioso
que conversáramos para profundizar en aspectos específicos?

●  Agradecemos enormemente su tiempo y la claridad sobre los aspectos técnicos.
Esta información es vital para que podamos diseñar soluciones que se puedan
construir de manera eficiente y que funcionen correctamente. Mantendremos una
comunicación estrecha a medida que avancemos en el diseño.

Notas Adicionales para el Entrevistador:

●  Utilizar un lenguaje que demuestre comprensión de conceptos técnicos básicos (ej.

APIs, escalabilidad, stack tecnológico) sin pretender ser un experto.
●  Estar preparado para que mencionen restricciones que no estaban en los

documentos y que pueden ser importantes.

●  Enfatizar cómo la colaboración temprana ayuda a evitar retrabajos costosos en

desarrollo. [Source 2872]

●  Si mencionan una limitación técnica, preguntar si hay alguna forma creativa (quizás

más simple) de lograr un objetivo similar desde el diseño.
